# AGENTS.md

## Cursor Cloud specific instructions

This repo is a single Python CLI product, **Contribution Copilot** (`contrib-pilot`), managed with **uv**. There is no web server, database, or Docker stack — everything runs as a CLI + subprocesses (Git, pytest). See `README.md`, `CUJS.md`, and `DESIGN.md` for full docs, and the README "Commands" table for the authoritative command list.

### Environment
- The startup/update script installs `uv` (to `~/.local/bin`, which is already on `PATH` via `~/.bashrc`) and runs `uv sync`. Dependencies live in the project-local `.venv/`; always invoke the tool through `uv run` (never call a globally-installed `contrib-pilot`).
- Python 3.12+ and Git are required and already present.

### Running the tool
- Setup commands (`doctor`, `demo reset`, `init`) run from the **repo root**: e.g. `uv run contrib-pilot doctor`.
- The contribution flow (`plan`, `scaffold`, `validate`, `review`, `report`, `run`) must run from **`demo/workspace/`** (that nested git repo holds the demo `config.toml`), and from there you must pass `--project ../..` so uv uses this package while cwd is the workspace: e.g. `cd demo/workspace && uv run --project ../.. contrib-pilot run ../issue.md --provider fixture`.
- `demo/workspace/` is a throwaway nested git repo regenerated by `uv run contrib-pilot demo reset` (from repo root) out of `demo/fixture/`. It is gitignored — never commit it. Reset it to get a clean state.
- The offline E2E demo uses `--provider fixture` (no network/API key). `--provider assistant` needs `ANTHROPIC_API_KEY` and is optional.
- `run` pauses once for approval before writing tracked files; pipe `y` (e.g. `echo y | uv run ...`) or use `--non-interactive` in automation.

### Testing / lint
- Run the tool's own suite from the repo root: `uv run pytest`.
- There is no separate lint tool configured (no ruff/flake8); "lint checks" in the docs refer to the tool's own validation feature, not a repo linter.
- Known pre-existing failures on Linux: `tests/unit/test_config.py::test_windows_separators_match_posix_allowlist` and `tests/unit/test_review.py::test_backslash_changed_paths_match_planned_files`. These assert Windows backslash (`pkg\a.py`) path normalization, which cannot hold on POSIX where `\` is a valid filename character. They are unrelated to environment setup.
